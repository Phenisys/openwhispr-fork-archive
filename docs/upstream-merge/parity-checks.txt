# Contrat de parité fonctionnelle — Phenisys/openwhispr
#
# Rôle : la liste des FONCTIONNALITÉS de la version officielle qui doivent
# exister dans notre arbre, même si leur écran d'origine vit dans un fichier
# que nous avons exclu (cloud / compte / workspace). L'audit
# `scripts/upstream-parity-audit.mjs` vérifie chacune d'elles après une fusion.
#
# Format : <id> | <aiguille littérale> | <globs> | [waived=<raison>]
#   - l'aiguille est une chaîne présente dans le CODE OFFICIEL (l'audit le
#     vérifie : une aiguille absente de l'amont rend la sonde PÉRIMÉE) ;
#   - elle doit apparaître chez nous dans au moins un fichier des globs ;
#   - `waived=` documente une absence ASSUMÉE (et la suite : issue, décision).
#
# Ajouter une ligne = promettre que la fonctionnalité reste. La supprimer =
# décider qu'elle n'est plus attendue. Les deux se relisent en revue.
#
# Ce que l'audit ne peut PAS voir : une fonctionnalité dont l'aiguille est un
# nom de variable local. En cas de doute, choisir un identifiant exporté, une
# clé d'événement IPC, ou le nom du composant.
